**Verification Standard:** Strict Non-Superficial Forensic Analysis

| # | Layer | Expected Behavior | Actual Behavior | Evidence | Root Cause | Required Fix |
| :---: | :--- | :--- | :--- | :--- | :--- | :--- |
| **1** | **UI / State Lifecycle** | When the user returns from the Android wallpaper confirmation dialog, the UI must automatically reflect the real active status ("Wallpaper Active" / "Manage Wallpaper"). | UI continues to show "Set as Live Wallpaper" with pulsing animation even after the user successfully sets the live wallpaper. | `ExamWallpaperWidget.tsx` lines 135–137: `setTimeout(() => checkIsLiveWallpaperActive().then(...), 1500)` executes before user confirms on the Android screen. No `App.addListener('appStateChange')` or window focus listener exists. | Transient timeout fires prematurely while the preview dialog is still open. When returning to the app, no lifecycle re-check is triggered. | Implement Capacitor `App.addListener('appStateChange')` and window `focus` listeners in `ExamWallpaperWidget` to re-query `checkIsLiveWallpaperActive()` upon app foregrounding. |
| **2** | **Native Bridge / Verification** | `isLiveWallpaperActive` must accurately confirm whether AspirantX's service is currently bound to the home or lock screen. | In some OEM Android flavors, `info.getServiceName()` may return short class names (e.g. `.AspirantXWallpaperService`) or differ from `AspirantXWallpaperService.class.getName()`. | `AspirantXWallpaperPlugin.java` line 113: `targetService.equals(currentService)`. | Direct string equality against `getName()` without checking `getPackageName()` or `ComponentName`. | Check both `info.getPackageName().equals(context.getPackageName())` AND `(info.getServiceName().endsWith("AspirantXWallpaperService"))` or `ComponentName` equality. |
| **3** | **Data Architecture / Theming** | When the user selects a Persona (e.g., Sung Jin-Woo, Naruto, Commandant) in the UI, the native live wallpaper must render using the selected persona's background gradient, accent colors, and quote. | The native live wallpaper only renders in the default deep-space navy theme (`#040714`), completely ignoring the user's selected persona and styling. | `nativeWallpaperBridge.ts` line 50: `WallpaperDataPayload` completely omits `personaId`, `bgGradient`, `accentColor`, `quote`. `AspirantXWallpaperService.java` line 152 hardcodes the background shader. | Data payload divergence between static canvas renderer and native wallpaper bridge. | Unify into ONE canonical `WallpaperState` containing persona ID, gradient colors, quote, and candidate name. Store and render them in `AspirantXWallpaperService`. |
| **4** | **Event Synchronization** | Changing a persona theme in the UI should immediately update the native live wallpaper in real time. | Changing persona only saves to `localStorage` (`aspirantx_wallpaper_persona_id`). The live wallpaper never updates. | `ExamWallpaperWidget.tsx` lines 113–118: `handleSelectPersona` calls only `localStorage.setItem`. `syncAuthoritativeWallpaperToNative` is never called. | Missing synchronization call upon theme/persona selection. | Call `syncAuthoritativeWallpaperToNative()` inside `handleSelectPersona()` to broadcast the new theme directly to the native service. |
| **5** | **Battery / Rendering Lifecycle** | Live wallpaper should only render on meaningful state changes (date change, data update, surface resize) and remain at 0% idle CPU. | Canvas redraws every 60 seconds (`ACTION_TIME_TICK`) when visible, draining battery unnecessarily. | `AspirantXWallpaperService.java` line 88: `filter.addAction(Intent.ACTION_TIME_TICK)`. | Redundant per-minute tick broadcast registration for a static day-level countdown wallpaper. | Remove `ACTION_TIME_TICK`. Keep only `ACTION_UPDATE_WALLPAPER`, `ACTION_DATE_CHANGED`, `ACTION_TIMEZONE_CHANGED`, and `ACTION_TIME_CHANGED`. |
| **6** | **UI State Machine** | UI must provide explicit state representation: `NOT_SUPPORTED`, `SUPPORTED`, `READY`, `PREVIEW_OPENED`, `ACTIVE`, `INACTIVE`, `REPLACED`. | UI only toggles between a binary boolean `isLiveActive`. It lacks user guidance when preview is opened or when the wallpaper has been replaced externally. | `ExamWallpaperWidget.tsx` lines 526–541. | Oversimplified binary state model without intermediate or diagnostic states. | Implement a formal `WallpaperStatus` state machine (`NOT_SUPPORTED`, `SUPPORTED`, `READY`, `PREVIEW_OPENED`, `ACTIVE`, `INACTIVE`, `REPLACED`) with dedicated UI badge and action buttons ("Set Wallpaper", "Manage Wallpaper", "Sync Data"). |
| **7** | **Simulated Permission Anti-Pattern** | Real wallpaper activation must rely solely on native Android `WallpaperManager` confirmation. | React code contains a fake permission flow with `aspirantx_wallpaper_permission` in `localStorage`. | `ExamWallpaperWidget.tsx` lines 59–65 and 163–169: `localStorage.getItem('aspirantx_wallpaper_permission') === 'granted'`. | Legacy simulated permission artifact from earlier web mockups. | Eliminate the fake permission check; derive all capabilities directly from `checkIsLiveWallpaperActive()` and Capacitor platform detection. |
| **8** | **Android 13/14 Broadcast Safety** | BroadcastReceiver in `AspirantXWallpaperService` must adhere to modern Android broadcast security requirements. | On Android 13+ (API 33+), registering `RECEIVER_NOT_EXPORTED` with system broadcasts (like `ACTION_DATE_CHANGED`) can produce runtime security exceptions or dropped broadcasts depending on OEM. | `AspirantXWallpaperService.java` lines 90–94: `registerReceiver(mReceiver, filter, Context.RECEIVER_NOT_EXPORTED)`. | Combining custom app broadcast (`ACTION_UPDATE_WALLPAPER`) with system protected broadcasts under `RECEIVER_NOT_EXPORTED`. | Separate into two receivers: one for internal app update broadcast (`RECEIVER_NOT_EXPORTED`) and one for system date change broadcasts. |
